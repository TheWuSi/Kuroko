## 1. 项目概述

### 1.1 项目定位
Kuroko 是一个专为影视番号管理与自动化离线下载设计的轻量化管理系统，基于 **OpenList API**（Alist 分支）生态构建。系统以磁力链接为输入，深度整合外部高性能 BT 元数据解析能力（对接开源 [felipemarinho97/magnet-metadata-api](https://github.com/felipemarinho97/magnet-metadata-api) 基于 DHT/Peer 网络的元数据提取）与 OpenList 网盘聚合能力，实现从磁力即时清洗、番号提取、存量去重、智能碎片空间匹配，到调用 PikPak 发起离线下载与全链路进度跟踪的闭环处理。

### 1.2 核心价值
- **前端即时净化与精准识别**：前端在用户填入磁力链接时立即剔除冗余 BT Tracker，保持链接可读；两阶段复核（`dn` 参数初筛 + BT 文件树深层识别）番号，准确率高。
- **智能化去重与多版本支持**：自动对比 OpenList 现有媒体库，避免重复下载浪费资源，同时保留「强制下载」通道支持同番号字幕版、高清重置版下载，并提供被跳过任务的可视化审计。
- **碎片空间优先算法 (Best-Fit Minimal Remainder)**：针对多个分散挂载的云存储节点，采用「满足容量前提下的最小剩余优先」策略，充分榨干各网盘存储碎片，全满时自动标记并顺延。
- **轻量定向探测与事件增量入库**：仅扫描配置的探测子路径，严禁全库递归遍历；下载完成后直接事件触发追加写入番号库，无需重扫库，极大降低 API 调用与性能损耗。
- **亮色优先与全端响应式美术设计**：采用现代白瓷科技（Porcelain Tech）亮色优先设计系统（配有深色切换），并深度适配手机端触控与布局（表格转卡片流、44px 触控区、抽屉导航），融合等宽字体与微交互动效。

### 1.3 核心业务流程

```mermaid
flowchart TD
    A[用户输入磁力链接] --> B[前端立即清洗 Tracker 仅留 xt/dn]
    B --> C[初步正则提取 dn 中的番号]
    B --> D[调用 magnet-metadata-api]
    D --> E[获取 DHT 文件列表并应用过滤规则]
    E --> F[从有效多媒体文件中二次复核番号]
    F --> G{查询库内番号记录}
    G -- 已存在 --> H[标记已存在 / 默认进入跳过队列]
    H --> I{用户强制执行下载?}
    I -- 是 (force: true) --> J[进入智能下载位置规划]
    I -- 否 --> K[保留跳过记录并结束]
    G -- 未存在 --> J[进入智能下载位置规划]
    J --> L[分组内筛选满足容量且剩余空间最小的节点]
    L --> M[调用 OpenList API 发起 PikPak 离线任务 (总是删除)]
    M --> N[后台轮询任务进度]
    N -- 下载完成 --> O[自动增量写入番号统计表 (无需重扫库)]
```

## 2. 功能需求

### FR-01 认证系统
- **FR-01-1 系统访问保护**：Kuroko 系统除登录接口外，所有 REST API 与管理页面均需受 JWT（JSON Web Token）认证机制保护。
- **FR-01-2 账号认证**：支持基于配置的用户名与密码进行身份认证。首次登录或密码验证通过后下发短期有效 Token，并支持会话保活与刷新。
- **FR-01-3 鉴权拦截**：未携带有效 `Authorization: Bearer <token>` 或 Token 过期失效的请求统一返回 `401 Unauthorized`，前端自动拦截并重定向至登录页。

### FR-02 磁力链接解析系统
- **FR-02-1 前端即时与后端双重清洗**：
  - 用户在前端输入/粘贴磁力链接时，**前端立即清理掉多余的 BT Tracker（`&tr=`）及统计参数**，保证磁力链接的可读性，仅保留核心 `xt`（Hash）与必要 `dn`（显示名称）；
  - 后端作为第二道防御线，严格校验并标准化 Magnet URI。
- **FR-02-2 初步番号提取**：基于 `dn` 参数通过正则提取番号，支持主流规则（如 `[A-Za-z]{2,5}-\d{3,5}`、`T28-\d{3}`、`FC2-PPV-\d{6,7}`、`HEYZO-\d{4}`、无横线及纯数字格式），并自动去除 `.torrent` 等后缀。
- **FR-02-3 接入 `magnet-metadata-api`**：
  - 引入开源服务 [felipemarinho97/magnet-metadata-api](https://github.com/felipemarinho97/magnet-metadata-api)，通过 `POST /api/v1/metadata` 传入 `{"magnet_uri": "..."}`；
  - 依靠 BitTorrent DHT/Peer 网络异步获取 Torrent 内部完整文件列表（包括相对路径、文件名、字节大小）；
  - 支持可配置超时（默认 45 秒）及超时优雅降级。
- **FR-02-4 文件名复核提取**：遍历解析出的实际多媒体文件名进行二次正则复核与修正，置信度高于单纯的 `dn` 名称。
- **FR-02-5 文件过滤管道**：对解析出的文件列表应用三重过滤规则：
  1. **后缀名白名单**：可在线配置，默认包含常见多媒体格式（如 `.mp4`, `.mkv`, `.avi`, `.ts`, `.wmv`）。
  2. **文件大小下限**：可在线配置，默认阈值为 `100MB`，自动剔除小样本、宣传片。
  3. **正则黑名单**：可在线配置正则表达式，针对常见广告词、发布组水印命名进行屏蔽过滤。
- **FR-02-6 过滤结果呈现**：被过滤文件标记原因标签（扩展名、体积、黑名单）；前端展示树状展开文件列表。

### FR-03 番号去重与强制下载
- **FR-03-1 库内比对**：将提取出的标准番号与系统维护的番号数据库进行快速精确查找。
- **FR-03-2 拦截与标记**：若番号已存在于库中，系统默认将该任务标记为「已存在」，并在批量添加/单任务添加队列中默认禁止加入离线下载队列。
- **FR-03-3 强制下载覆盖通道**：针对特异化场景（如已下载版本为无字幕版，当前磁力为中字或 4K 高码版本），前端提供明确的「强制下载」操作按钮，允许用户显式绕过去重校验执行下载。
- **FR-03-4 跳过记录与可视化**：因重复而被跳过的磁力链接需集中呈现在「已跳过」面板中，明确标记跳过原因和库内已存在文件的存储路径，方便审计。

### FR-04 OpenList 文件获取与空间统计
- **FR-04-1 接口通信**：通过 OpenList 标准接口（如 `/api/fs/list`）获取指定挂载存储和目录下的文件结构与属性元数据。
- **FR-04-2 剩余空间感知**：
  - **自动模式**：若 OpenList 存储接口能原生返回当前存储库的剩余空间（`free_size`），系统直接读取采用。
  - **手动补偿模式**：若挂载源未返回剩余空间，支持用户在前端管理后台手动标记该存储库的总空间容量（Quota）。系统通过递归统计库内已有文件的累计体积，以 `总容量 - 已用容量` 动态推算剩余空间。
- **FR-04-3 分库空间拓扑**：前端以存储库为单位展示存储拓扑，直观呈现总容量、已用空间、剩余空间百分比及碎片率。

### FR-05 离线下载引擎
- **FR-05-1 接口调用**：通过 OpenList 官方 `/api/fs/add_offline_download` 接口投递下载任务。
- **FR-05-2 引擎与策略绑定**：
  - 下载工具固定指定为 `PikPak`（`tool: "pikpak"`）。
  - 下载完成后的删除策略固定为「总是删除」（`delete_policy: "always"`），即离线成功转存至目标存储后，自动清理 PikPak 云端缓存，节约空间。
- **FR-05-3 落地目录反馈**：任务发起成功后，系统即时记录并向前端与日志反馈最终规划的目标落地路径（如：`/OD-Group1/NodeA/Video/ABC-123/`）。

### FR-06 智能下载位置规划
- **FR-06-1 存储分组模型**：支持多存储节点分组管理机制。一个存储分组（Storage Group）下纳管多个 OpenList 挂载节点（Storage Node）。
- **FR-06-2 碎片空间优先算法 (Best-Fit Minimal Remainder)**：
  - 用户提交下载请求并指定目标分组后，系统计算该磁力待下载有效文件的总尺寸。
  - 在候选分组的所有可用存储节点中，筛选出 `剩余空间 >= 待下载文件大小` 的可用节点集合。
  - **排序策略**：在上述可用节点中，优先选择**剩余空间最小**的节点作为下载目标，充分利用存储碎片。
- **FR-06-3 自动顺延机制**：若剩余空间最小的节点空间不足以容纳当前任务，自动顺延至集合中下一个较小的可用节点；若分组内所有节点均无法容纳，阻断下载并报警提示。
- **FR-06-4 满载状态流转**：当存储节点剩余空间低于预设安全阈值时，节点在调度拓扑中被标记为「已满」，不再分配新任务。
- **FR-06-5 规划结果输出**：明确输出文件最终下载到的目录。

### FR-07 下载进度同步
- **FR-07-1 定时状态轮询**：前端或后台启动轮询调度，拉取任务最新状态（增量同步）。
- **FR-07-2 状态模型映射**：将底层状态归一化为：`pending`（等待中）、`downloading`（下载中）、`completed`（已完成）、`failed`（失败）。
- **FR-07-3 动态指标展示**：前端提供任务进度面板，展示下载百分比进度条、传输速率、目标落地路径及异常错误原因。

### FR-08 番号统计与库管理
- **FR-08-1 定向探测路径配置**：
  - 支持配置「探测路径」（Probe Path），每个探测路径精准绑定特定存储库的具体子目录（如存储库 `OD` 仅配置 `/Video1` 和 `/Video2`）。
- **FR-08-2 极速扫描与频控保护**：严格限制扫描范围仅在配置的探测子目录内，**禁止执行根目录全库递归深度遍历**，极大减少 API 交互与时间，防止触发上游限流。
- **FR-08-3 规则一致性过滤**：扫描过程复用文件扩展名、最小体积、广告正则黑名单规则，过滤无效内容。
- **FR-08-4 元数据持久化**：从合规文件中解析番号，建立并持久化「番号统计表」。
- **FR-08-5 离线成功自动增量入库**：当离线下载任务完成确认后，直接从任务元数据中将新番号追加写入番号统计库，**无需触发重新扫库**，保证实时性与开销最小化。

### FR-09 前端在线配置
- **FR-09-1 统一配置中枢**：支持通过 Web 前端可视化界面管理系统核心配置，即时生效：
  - **OpenList 连接设置**：服务 Base URL、认证凭证（支持**账号密码登录**与**令牌直连**双模式）、连通性测试。
  - **magnet-metadata-api 设置**：解析服务地址（URL）、超时时间配置、连通性与 DHT 状态测试。
  - **内容过滤规则**：文件扩展名白名单（Tag 形式增删）、最小文件大小（MB）、广告/无效文件名正则表达式黑名单。
  - **存储分组与节点**：创建与编辑分组，增删分组所属的存储节点及其根路径。
  - **探测路径管理**：可视化选择或填报定向扫描的存储库路径。
  - **容量标记覆盖**：针对无原生空间查询的存储源，手动填报总容量上限。

### FR-10 GitHub Actions CI/CD
- **FR-10-1 Tag 自动触发**：支持基于 Git Tag 推送事件（如 `v*.*.*`）自动触发 CI/CD 工作流。
- **FR-10-2 镜像自动构建与发布**：自动化前端编译与打包、后端测试，构建多架构 Docker 镜像推送至 **GitHub Container Registry (GHCR)**，打上版本 Tag 及 `latest` 标签。

### FR-11 Docker 部署
- **FR-11-1 容器化交付**：前端构建产物并入后端，由 FastAPI 统一提供静态文件和 API 服务，以 `python -m app.serve` 为容器启动入口。
- **FR-11-2 联合编排**：提供 `docker-compose.yml`，联合编排 `kuroko`、`magnet-metadata-api` 与 `redis` 容器，开箱即用。
- **FR-11-3 端口可配置**：服务监听端口通过环境变量（`.env`）灵活指定（支持配置后端端口与前端访问端口）。

## 3. 技术栈选型

| 领域 | 选型组件 | 说明 / 选型理由 |
| :--- | :--- | :--- |
| **后端语言** | Python 3.12+ | 现代化强类型提示与高性能异步特性 |
| **后端 Web 框架** | FastAPI | 高性能异步 REST API，自动 OpenAPI 文档，Pydantic v2 强校验 |
| **ORM 与数据层** | SQLAlchemy 2.0+ & SQLite | 关系映射清晰，轻量单文件数据库，免除外部 DB 维护 |
| **BT 元数据解析引擎** | magnet-metadata-api (Go) | 基于 BitTorrent DHT/Peer 网络，Redis 内存加速，支持容器集成 |
| **前端框架** | React 19 & TypeScript | 强类型组件化，生态成熟稳定 |
| **前端构建工具** | Vite | 毫秒级热重载与生产高效打包 |
| **UI 组件库与样式** | Shadcn/ui & Tailwind CSS (v4) | 高度可定制，基于 Radix UI 无障碍标准 |
| **前端状态管理** | Zustand | 轻量、无样板代码，原生支持切片与数据流隔离 |
| **前端 HTTP 客户端** | Axios | 统一拦截器、自动 Token 注入、401 隔离、AbortController 取消 |
| **美术与视觉规范** | Porcelain Tech (白瓷科技亮色优先) | 现代高质感亮色优先、支持暗色切换，深度适配手机端响应式布局 |
| **构建与编排** | Make & Docker Compose | 统一本地命令与多服务容器协同 |
