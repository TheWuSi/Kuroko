## 1. 项目概述

### 1.1 项目定位
Kuroko 是一个专为影视番号管理与自动化离线下载设计的轻量化管理系统，基于 **OpenList API**（Alist 分支）生态构建。系统以磁力链接为输入，深度整合外部高性能 BT 元数据解析能力（对接开源 [felipemarinho97/magnet-metadata-api](https://github.com/felipemarinho97/magnet-metadata-api) 基于 DHT/Peer 网络的元数据提取）与 OpenList 网盘聚合能力，实现从磁力即时清洗、番号提取、存量去重、智能碎片空间匹配，到调用 PikPak 发起离线下载与全链路进度跟踪的闭环处理。

### 1.2 核心价值
- **前端即时净化与精准识别**：前端在用户填入磁力链接时立即剔除冗余 BT Tracker，保持链接可读；两阶段复核（`dn` 参数初筛 + BT 文件树深层识别）番号，准确率高。
- **智能化去重与多版本支持**：自动对比 OpenList 现有媒体库，避免重复下载浪费资源，同时保留「强制下载」通道支持同番号字幕版、高清重置版下载，并提供被跳过任务的可视化审计。
- **组内节点优先级与容量顺延**：满足完整下载容量的节点按优先级从高到低使用，同优先级按最小剩余空间选择；空间不足时切换到下一可用节点。
- **定向探测与真实文件入库**：仅扫描配置的探测子路径。离线成功与转存完成分开显示，番号库只记录实际扫描到的文件。
- **亮色优先与全端响应式美术设计**：采用现代白瓷科技（Porcelain Tech）亮色优先设计系统（配有深色切换），并深度适配手机端触控与布局（表格转卡片流、44px 触控区、抽屉导航），融合等宽字体与微交互动效。

### 1.3 核心业务流程

```mermaid
flowchart TD
    A[用户输入磁力链接] --> B[前端立即清洗 Tracker 仅留 xt/dn]
    B --> C[初步正则提取 dn 中的番号]
    B --> D[调用 magnet-metadata-api]
    D --> E[获取 DHT 文件列表并应用过滤规则]
    E --> F[从有效多媒体文件中二次复核番号]
    F --> G{查询库内番号记录}
    G -- 已存在 --> H[标记已存在 / 默认进入跳过队列]
    H --> I{用户强制执行下载?}
    I -- 是 (force: true) --> J[进入智能下载位置规划]
    I -- 否 --> K[保留跳过记录并结束]
    G -- 未存在 --> J[进入智能下载位置规划]
    J --> L[直接使用指定目录，或按完整种子大小从分组选择目录]
    L --> M[调用 OpenList API 发起 PikPak 离线任务 (总是删除)]
    M --> N[后台轮询任务进度]
    N -- 离线完成 --> O[查看独立转存任务，实际扫描文件后入库]
```

## 2. 功能需求

### FR-01 认证系统
- **FR-01-1 系统访问保护**：Kuroko 系统除登录接口外，所有 REST API 与管理页面均需受 JWT（JSON Web Token）认证机制保护。
- **FR-01-2 账号认证**：支持基于配置的用户名与密码进行身份认证。登录与首次初始化同时签发短期访问令牌、刷新令牌及过期时间。前端在访问令牌临近过期或收到 401 时无感续期；并发请求共用一次刷新，原请求最多重试一次。
- **FR-01-3 鉴权拦截**：未携带有效 `Authorization: Bearer <token>` 或 Token 过期失效的请求统一返回 `401 Unauthorized`，前端先尝试续期，刷新凭证确定失效才进入登录页；网络中断或 5xx 保留登录信息。重新登录返回原页面，退出或换账号后忽略旧请求响应。

### FR-02 磁力链接解析系统
- **FR-02-1 前端即时与后端双重清洗**：
  - 用户在前端输入/粘贴磁力链接时，**前端立即清理掉多余的 BT Tracker（`&tr=`）及统计参数**，保证磁力链接的可读性，仅保留核心 `xt`（Hash）与必要 `dn`（显示名称）；
  - 后端作为第二道防御线，严格校验并标准化 Magnet URI。
  - Hash 仅接受 40 位十六进制或 32 位 Base32，统一转为小写十六进制。
  - 输出和上游提交必须保留 `xt=urn:btih:` 的冒号，禁止生成 `urn%3Abtih%3A`；兼容读取旧编码并纠正。`dn` 中的中文、空格和参数分隔符仍安全编码。
- **FR-02-2 初步番号提取**：基于 `dn` 参数通过正则提取番号，支持主流规则（如 `[A-Za-z]{2,5}-\d{3,5}`、`T28-\d{3}`、`FC2-PPV-\d{6,7}`、`HEYZO-\d{4}`、无横线及纯数字格式），并自动去除 `.torrent` 等后缀。
  - **数字字母混合前缀**：支持以数字开头的番号前缀，如 `300MIUM-777`、`259LUXU-1234`、`200GANA-2345`，允许横线、下划线或紧跟数字的写法。前缀本身须同时含数字与字母，避免把发布组编号误当成番号。此类前缀整体保留，不再插入横线。
- **FR-02-1b 剪贴板快捷粘贴**：磁力输入区提供「读取剪贴板」按钮，点击后读取剪贴板文本并以**新行追加**到输入框末尾，**绝不替换**已有草稿，方便手机端多次复制后连续粘贴。优先使用异步剪贴板接口，权限被拒或非安全上下文时回退到兼容方案；无法读取、内容为空或与现有输入重复时给出明确提示，不做静默丢弃。读取结果同样经过前端清洗，超出草稿容量上限时拒绝写入并保留原输入。
- **FR-02-3 接入 `magnet-metadata-api`**：
  - 引入开源服务 [felipemarinho97/magnet-metadata-api](https://github.com/felipemarinho97/magnet-metadata-api)，通过 `POST /api/v1/metadata` 传入 `{"magnet_uri": "..."}`；
  - 依靠 BitTorrent DHT/Peer 网络异步获取 Torrent 内部完整文件列表（包括相对路径、文件名、字节大小）；
  - 支持可配置超时（默认 45 秒）及超时优雅降级。
- **FR-02-4 文件名复核提取**：遍历解析出的实际多媒体文件名进行二次正则复核与修正，置信度高于单纯的 `dn` 名称。
- **FR-02-5 文件过滤管道**：对解析出的文件列表应用三重过滤规则：
  1. **后缀名白名单**：可在线配置，默认包含常见多媒体格式（如 `.mp4`, `.mkv`, `.avi`, `.ts`, `.wmv`）。
  2. **文件大小下限**：可在线配置，默认阈值为 `100MB`，自动剔除小样本、宣传片。
  3. **正则黑名单**：可在线配置正则表达式，针对常见广告词、发布组水印命名进行屏蔽过滤。
- **FR-02-6 过滤结果呈现**：被过滤文件标记原因标签（扩展名、体积、黑名单）；前端展示文件列表与完整种子大小。过滤只影响识别和展示，PikPak 下载包含整个种子。文件树按需读取，轮询仅传输条目摘要。

- **FR-02-7 输入防丢失**：按账号在当前浏览器即时保存磁力草稿，包括未输完的内容、下载位置和关联批次；刷新、切页、关闭页面和重新登录后恢复。缓存失败明确提示且不清空输入；后台结果不得覆盖后来编辑或另一标签页保存的新草稿。
- **FR-02-8 长耗时后台解析**：每条磁力必须等待元数据 API 返回。每批 1～100 条，每账号同时运行一个批次，后台解析池并发条数可配置（默认四条，上限十六条），并受全局并发上限保护，逐条保存并保持输入顺序，不设整批总时限，保留单次请求超时。页面关闭及 JWT 失效不影响执行，重启后继续未完成项；停止后保留结果，可继续或仅重试失败项。展示数量、等待条目及耗时，运行中每两秒读取状态，短暂失败退避重试。
- **FR-02-9 元数据过载保护与自动重试**：元数据服务超时、过载（HTTP `503`/`429`）或连接失败时不再直接判失败，按指数退避（含抖动，上限 30 秒，并遵循 `Retry-After`）安排下次尝试，默认最多三次。重试等待时间持久化，进程重启后按计划继续；等待期间条目标记「等待重试」并展示下次时间。过载错误不消耗重试次数，直接重新排队，避免在服务恢复前放大压力。
- **FR-02-10 手工修改番号**：解析结果中每条可手工指定番号，保存后立即按新番号重算版本、分集与查重结论；留空表示放弃识别（提交时记为 `UNKNOWN`），另有「恢复自动识别」回到自动结果。手工番号随条目保留，元数据重试或恢复解析都不会被自动结果覆盖。

### FR-03 番号去重与强制下载
- **FR-03-1 库内比对**：将提取出的标准番号与系统维护的番号数据库进行快速精确查找。
  - 比对范围为目标分组所有成员的下载目录与归档目录，分组之间独立；同目录属于多个分组时须同时满足各分组规则。未分组目录可直接下载，仅检查该目录范围内的索引。
  - `FC2-1234567` 与 `FC2-PPV-1234567` 视作同一番号，统一保存为 `FC2-PPV-1234567`。版本单独保存为 `original/C/UC/U`。
  - FC2 的无后缀文件与 `(1)/(2)`、`-1/-2`、`CD1/CD2`、`part1/part2` 等分集分别识别，同版本不同集自然共存；同集跨盘出现仍提示重复。扫描、解析预检与下载提交使用同一规则，多文件种子保存完整分集集合，分集信息不明时保守查重。
- **FR-03-2 拦截与标记**：若番号已存在于库中，系统默认将该任务标记为「已存在」，并在批量添加/单任务添加队列中默认禁止加入离线下载队列。
- **FR-03-3 强制下载覆盖通道**：针对特异化场景（如已下载版本为无字幕版，当前磁力为中字或 4K 高码版本），前端提供明确的「强制下载」操作按钮，允许用户显式绕过去重校验执行下载。
- **FR-03-4 跳过记录与可视化**：因重复而被跳过的磁力链接需集中呈现在「已跳过」面板中，明确标记跳过原因和库内已存在文件的存储路径，方便审计。
- **FR-03-5 持久化版本放行**：按「分组＋番号」保存已允许共存的版本集合，集合内每个版本只允许一份；FC2 按每个版本的每一分集各一份计算。移动文件不撤销规则；同版本再次重复或出现未批准版本仍提示。提供查看与撤销入口，解析预检和下载提交复用规则，等待/下载中的任务也参与提交查重。
- **FR-03-6 重复信息优先展示与默认不保留**：解析结果中「库内已存在」的条目**置顶展示**（同组内保持原始顺序），便于优先确认是否保留；每条仍可查看库内路径并选择「强制下载」。批次收尾时**默认不保留**这些重复项——从输入框移除，避免下次解析重复占用；确实需要继续处理的场景可通过恢复解析的保留选项留在输入框。移除仅作用于输入草稿，解析结果与跳过记录仍然保留可查。

### FR-04 OpenList 文件获取与空间统计
- **FR-04-1 接口通信**：通过 OpenList 标准接口（如 `/api/fs/list`）获取指定挂载存储和目录下的文件结构与属性元数据。
- **FR-04-2 剩余空间感知**：
  - **自动模式**：读取 OpenList v4.2.6 的 `mount_details.total_space/used_space/free_space`，缺失时查询挂载根目录的 `mount_details`。驱动返回 `total_space=0` 表示未提供有效配额，不当作磁盘已满。
  - **手动补偿模式**：按真实 OpenList 存储 ID 设置总配额，优先使用原生已用容量；必要时在当前挂载内完整统计。单次容量查询/统计预算为 30 秒，目录/文件数设上限；嵌套挂载、权限失败或超预算时，容量保持未知并返回原因。保存配额不等于统计成功。手动配额可重置为自动获取，原生容量不可用时显示未知并保留原因。
- **FR-04-3 分库空间拓扑**：前端以存储库为单位展示存储拓扑，直观呈现总容量、已用空间、剩余空间百分比及碎片率。
- **FR-04-4 可撤销的节点忽略**：按真实存储 ID 持久化忽略项，默认隐藏，不参与容量汇总、下载调度、直接下载和新扫描；单独面板可查看并恢复，保留已有目录配置与索引。
- **FR-04-5 容量汇总与缓存**：未知容量在节点上保持「未知」，汇总时按零计算，不影响其他节点。后端存储、容量、目录等读取使用有界短时缓存与同键并发请求合并；前端缓存节点、分组和忽略项，在同一浏览器会话中跨页面、跨刷新复用成功结果并显示更新时间。离线、转存、扫描任务进入终态、相关配置变化或手动刷新时更新。配置凭据变化与不同用户隔离缓存，失败保留同一数据源的成功结果。展示缓存不参与调度容量判断。

### FR-05 离线下载引擎
- **FR-05-1 接口调用**：通过 OpenList 官方 `/api/fs/add_offline_download` 接口投递下载任务。
- **FR-05-2 引擎与策略绑定**：
  - 下载工具固定指定为 `PikPak`（大小写敏感）。
  - 使用 `delete_policy: "delete_always"`，具体转存与清理由 OpenList 执行。
- **FR-05-3 落地目录反馈**：直接使用指定的绝对目录，例如 `/OD-Group1/NodeA/Video`，不追加番号或任务 ID 子目录，不执行刮削、重命名或文件整理。未指定目录时兼容分组调度。
- **FR-05-4 批量可靠性**：返回 `submitted/skipped/failed`，各项包含输入索引和磁力。逐项保存结果，后续失败不回滚已提交任务；提交结果不明时保留待核实任务，不自动重试。

- **FR-05-5 后台提交与账号历史**：提交下载也作为长任务，先持久化批次和请求编号，再逐条提交与保存结果。相同请求编号重试返回原任务，不重复投递；重启后仅继续尚未开始的条目，已经开始的提交须通过本地下载凭据核实，无法确认则标记待核实。
- **FR-05-6 提交后交互**：提交结束后移出成功项（包括已存在的待处理任务），重复跳过、失败、待核实及未提交项保留，全部成功才清空。最近记录按账号保存完整输入、目标和逐条结果，每页 20 批、不自动过期；点击恢复输入和解析结果，原草稿可撤销恢复。恢复不自动提交，位置和重复记录须重新核对，保留已提交及待核实状态。

### FR-06 智能下载位置规划
- **FR-06-1 存储分组模型**：支持多存储节点分组管理机制。一个存储分组（Storage Group）下纳管多个 OpenList 挂载节点（Storage Node）。
  - 通过勾选真实存储节点创建分组，每个成员设置一个下载目录和零到多个归档目录，支持浏览 OpenList 文件夹选择。
  - 同一存储可加入多个分组，每组独立配置目录；同组不可重复选择同一节点。新配置必须绑定具体子目录，避免扫描整个挂载。
- **FR-06-2 节点优先级调度**：
  - 用户未指定目录时，后端向元数据服务核实整个种子的大小，不采信客户端大小或过滤后的文件总和。容量未知或完整大小未知时不能自动调度。
  - 在候选分组的所有可用存储节点中，筛选出 `剩余空间 >= 待下载文件大小` 的可用节点集合。
  - 每个分组成员配置 0～9999 的整数优先级，默认 0，数值越大越优先；同一节点在不同组中独立设置。旧客户端更新目录时保留已有优先级。
  - **排序策略**：候选节点按优先级降序选择，同优先级按剩余空间升序选择；计算可用空间时扣除等待及下载中任务的完整预留体积。
- **FR-06-3 自动顺延机制**：高优先级节点空间不足时，选择下一可用节点；已忽略、状态异常或容量未知的节点不参与自动选择。若所有节点均无法容纳，阻断下载并提示原因。
- **FR-06-4 满载状态流转**：当存储节点剩余空间低于预设安全阈值时，节点在调度拓扑中被标记为「已满」，不再分配新任务。
- **FR-06-5 规划结果输出**：明确输出文件最终下载到的目录。

### FR-07 下载进度同步
- **FR-07-1 定时状态轮询**：前端或后台启动轮询调度，拉取任务最新状态（增量同步）。
- **FR-07-2 状态模型映射**：依据上游数字 `state` 归一化为 `pending/downloading/completed/failed/cancelled`；离线与转存分开查询，不推测缺失的父子关系，任务消失不等于完成。
- **FR-07-3 动态指标展示**：展示百分比、目录和错误。上游没有独立速率字段时显示未知，下载字节数标记为估算。取消操作仅发送请求，等待上游确认终态，不删除文件。

### FR-08 番号统计与库管理
- **FR-08-1 定向探测路径配置**：
  - 支持配置「探测路径」（Probe Path），每个探测路径精准绑定特定存储库的具体子目录（如存储库 `OD` 仅配置 `/Video1` 和 `/Video2`）。
  - 新配置统一使用分组成员的下载和归档目录；扫描前展示完整范围，可选单组或所有配置目录。旧探测配置在升级时合并到对应成员，未匹配项继续保留。
- **FR-08-2 长耗时扫描与频控保护**：扫描后台运行，启动后立即返回任务编号，保存启动时的目录范围。取消单根五分钟总时限，保留单次请求超时、5000 个目录和 100000 个条目的单根上限；**禁止执行根目录全库递归深度遍历**。切页和刷新后恢复跟踪，短暂状态读取失败自动重试；展示范围完成度、已扫文件／目录、当前路径和耗时。支持取消，服务重启后标记中断并允许重新发起。
- **FR-08-3 规则一致性过滤**：扫描过程复用文件扩展名、最小体积、广告正则黑名单规则，过滤无效内容。
- **FR-08-4 元数据持久化**：从合规文件中解析番号，建立并持久化「番号统计表」。
- **FR-08-5 转存后确认入库**：通过定向扫描发现真实落地文件后写入番号库。离线完成不直接入库，不猜测文件名和路径。
- **FR-08-6 索引同步与重复提示**：完整扫描一个目录后更新索引并移除该目录失效的扫描记录，取消、权限失败或扫描不完整时保留未完成范围的旧记录。文件名缺少番号时可从作品目录识别。组内跨盘重复展示实际文件路径、版本、分集及命中的下载／归档目录。每个项目右侧均显示共存按钮，真实重复时禁用并说明原因。目录重叠按最长匹配判断，完全重合时保留双标签，不移动或删除文件。
- **FR-08-7 归档统计**：页面突出显示当前分组及搜索条件下的去重番号总数和媒体文件总数；分集、多版本分别计文件，分页仍按文件记录。

### FR-09 前端在线配置
- **FR-09-1 统一配置中枢**：支持通过 Web 前端可视化界面管理系统核心配置，即时生效：
  - **OpenList 连接设置**：服务 Base URL、认证凭证（支持**账号密码登录**与**令牌直连**双模式）、连通性测试。
  - **magnet-metadata-api 设置**：服务地址、1～300 秒解析超时、可选代理认证令牌及健康测试；健康接口不表示 DHT 可用。未保存的表单值可直接测试，凭据掩码回传时保留原值。
  - **内容过滤规则**：文件扩展名白名单（Tag 形式增删）、最小文件大小（MB）、广告/无效文件名正则表达式黑名单。
  - **存储分组与节点**：选择 OpenList 存储节点，逐个浏览并配置下载与归档目录，管理可撤销的节点忽略项。
  - **探测路径管理**：可视化选择或填报定向扫描的存储库路径。
  - **容量标记覆盖**：针对无原生空间查询的存储源，手动填报总容量上限。

### FR-10 GitHub Actions CI/CD
- **FR-10-1 Tag 自动触发**：支持基于 Git Tag 推送事件（如 `v*.*.*`）自动触发 CI/CD 工作流。
- **FR-10-2 镜像自动构建与发布**：自动化前端编译与打包、后端测试，构建多架构 Docker 镜像推送至 **GitHub Container Registry (GHCR)**，打上版本 Tag 及 `latest` 标签。

### FR-11 Docker 部署
- **FR-11-1 容器化交付**：前端构建产物并入后端，由 FastAPI 统一提供静态文件和 API 服务，以 `python -m app.serve` 为容器启动入口。
- **FR-11-2 联合编排**：提供 `docker-compose.yml`，联合编排 `kuroko`、`magnet-metadata-api` 与 `redis` 容器，开箱即用。
- **FR-11-3 端口可配置**：服务监听端口通过环境变量（`.env`）灵活指定（支持配置后端端口与前端访问端口）。
